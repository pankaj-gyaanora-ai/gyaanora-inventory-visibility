The availability formula

The formula is defined over buckets in configuration, not over sources in code. Change a sign below and every number on this page recomputes — that is exactly what editing sources.yaml does in production, with no deployment.

Live sandbox. Toggling a sign here mirrors a one-line YAML change reviewed by Ops. The classic mistake — counting inbound stock as sellable today — is one click away, and the impact is measurable.

Why inbound is excluded

Units on a supplier PO are not sellable today. Adding them to available is the specific arithmetic that produced this quarter's oversells. They are kept in a separate atp_7d field with a date horizon, so the dashboard can honestly say "80 now, 180 by Friday" without ever letting Friday's stock be sold on Wednesday.

Fail-closed vs fail-open

      
Overstating availability costs chargebacks and a customer.
         Understating it costs a little deferred revenue. So every ambiguity resolves downward, and the
         missing-feed policy differs by whether the feed subtracts or adds.

      
Order feed missing → abort. Losing RESERVED would inflate every number
        on the dashboard. The run stops, the previous publication stays live, ops is paged.

      
Supplier feed missing → complete, degraded. Only ATP is affected, and it can
        only understate. The run finishes and raises DEGRADED_RUN.

How every number is calculated

  
Each formula below is the exact arithmetic the engine runs, shown with a real row
     from today's published run. Nothing here is illustrative — the values match the cards above.


  
Deterministic core: same inputs → byte-identical outputs. Every figure traces to source rows.


  

    
1 · Availability (the one true number)

    
available = Σ ( quantity × available_sign[bucket] )
          = on_hand − reserved − unsellable − safety_stock

    
Example — MSD-2077 (Wiper blade Heavy duty):

    
available = 812 − 1017 − 0 − 0  =  −205
published = max(0, −205)       =   0     ← can't sell a negative
raw_available kept as −205               ← the shortfall IS the signal

  


  

    
2 · Available to promise (future)

    
atp_7d = available + Σ ( INBOUND where eta ≤ today + 7 days )

    
Inbound has available_sign = 0 so it never
       inflates today's number — it only counts toward ATP, with a date attached.

  


  

    

      
3 · Oversold shortfall

      
sellable_on_hand = on_hand − unsellable
shortfall        = reserved − sellable_on_hand

      
MSD-2077: 1017 − 812 = 205 units short

    


    

      
4 · Revenue at risk

      
exposure = shortfall × unit_price

      
MSD-2077: 205 × $84.16 = $17,252.80

         Card total = Σ exposure over 22 oversold SKUs = $109,484

    

  


  

    
5 · The overstatement (naive vs true)

    
naive             = total_on_hand + total_inbound
                  = 293,135 + 16,173  =  309,308

overstatement_u   = naive − total_available
                  = 309,308 − 209,160 =  100,148
overstatement_pct = 100,148 / 309,308 × 100  =  32.4%

  


  

    

      
6 · Feed health

      
age_hours = now − feed.export_time
stale     = age_hours > feed.sla_hours

      
WMS: 1.25h old, SLA 6h → healthy. Snapshot skew =
         max(as_of) − min(as_of) = 110 min today.

    


    

      
7 · Risk score (advisory, 0–100)

      
score = Σ ( component × weight )   # weights in YAML, not a model

      
MSD-2077: 30 (stockout) + 28 (oversold) + 12 (penalty)
         + 11 (revenue) = 81.0
